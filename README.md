# oncoco-proto

Vibe prototyping of *oncoco*, a compuviz collector assistant.

The prototype explore the following concepts:
- PWA that requests rear camera access.
- JS based computer vision using off the shelf algorithms and models

Static PWA (Vite + TypeScript, no UI framework): full-screen rear camera feed, overlay canvas, hot-swappable vision algorithms and a performance overlay. Targets: Safari iOS 26+ and recent Chrome Android.

## Running locally

```sh
npm install
npm run dev        # http://localhost:5173 (desktop)
npm run dev:host   # also listens on the LAN IP, for testing on mobile
```

**Camera and HTTPS.** `getUserMedia` is only available in a secure context (HTTPS or `localhost`). With `npm run dev:host`, the URL `http://192.168.x.x:5173` opened on a phone is **not** a secure context: the app displays "Insecure context". There are several ways to test on mobile:

- **HTTPS tunnel** (simplest, iOS and Android): `npm run dev`, then, in another terminal,
  `cloudflared tunnel --url http://localhost:5173` (or `ngrok http 5173`), and open the `https://…` URL it provides.
  If Vite rejects the host, add `server: { allowedHosts: true }` to `vite.config.ts` (locally only).
- **Chrome Android over USB**: enable USB debugging, open `chrome://inspect` on the PC → *Port forwarding* `5173 → localhost:5173`. On the phone, `http://localhost:5173` is then a secure context.
- **Local certificate**: generate a certificate for the LAN IP with [mkcert](https://github.com/FiloSottile/mkcert), pass it to Vite via `server.https: { key, cert }`, and install the mkcert CA on the phone (on iOS: Settings → General → About → Certificate Trust Settings).
- **Build preview**: `npm run build && npm run preview`, exposed the same way. Useful for testing the service worker, which is not active in dev.

Debugging: Safari iOS → Web Inspector from Safari on a Mac (Settings → Safari → Advanced → Web Inspector); Chrome Android → `chrome://inspect`.

## Deployment (GitHub Pages)

The workflow [.github/workflows/deploy.yml](.github/workflows/deploy.yml) builds and publishes `dist/` on every push to `main` (and on demand via *Run workflow*).

1. One time only: *Settings → Pages → Build and deployment → Source: GitHub Actions*.
2. Push to `main`. The app is served at `https://<user>.github.io/oncoco-proto/`.

The base path is defined by `REPO_BASE` in [vite.config.ts](vite.config.ts) (`/oncoco-proto/`, applied at build time only). It must be changed if the repository is renamed.

The PWA icons are placeholders generated by `npm run gen:icons` ([scripts/gen-icons.mjs](scripts/gen-icons.mjs)) into `public/icons/`.

## Architecture

```
src/
  main.ts               assembly: UI, camera, loop, algorithm host
  worker.ts             processing worker: loads and runs the algorithms' processors
  core/                 does not depend on any concrete algorithm
    camera.ts           getUserMedia + typed errors (permission, missing device, insecure context…)
    loop.ts             requestVideoFrameCallback (rAF fallback), one frame at a time, frames skipped when busy
    frameSource.ts      video → downscaled ImageData / VideoFrame / nothing depending on the algorithm
    coords.ts           CoordMapper: source coordinates → canvas, with object-fit: cover cropping
    algoHost.ts         hot swapping (worker load / renderer), cancellation, remembers the choice
    workerClient.ts     main-thread side of the worker: requests → promises
    workerProtocol.ts   messages exchanged with the worker
    perf.ts             FPS, processing time, round trip (moving averages over 30 frames), skipped frames
  ui/dom.ts             DOM elements (start screen, selector, perf overlay, loader, errors)
  algorithms/
    types.ts            AlgorithmEntry, Processor (worker) and Renderer (main thread) interfaces
    registry.ts         declarative list of algorithms (shared by the page and the worker)
    passthrough.ts      no processing (baseline: loop + worker round trip)
    sobel.ts            grayscale + Sobel as a semi-transparent overlay (renderer)
    sobel.processor.ts    … computation (worker)
    houghCircles.ts     circle detection (simplified gradient Hough) (renderer)
    houghCircles.processor.ts … computation (worker)
    lib/imageOps.ts     shared operations (grayscale, blur, Sobel)
```

**Threads.** All algorithm computation runs in a dedicated module worker, so the UI stays responsive whatever the processing time. The main thread grabs the frame (downscaled `ImageData`, or a `VideoFrame`) and *transfers* it to the worker without copying. The worker runs `process` and sends the result back, transferring it too if the processor says so. The main thread then draws it on the overlay canvas. The perf overlay shows `proc` (time spent in `process`, measured in the worker) and `rtt` (from frame capture to result reception, including transfers).

The only use of `localStorage` is the `oncoco.algo` key (selected algorithm).

## Adding an algorithm

An algorithm has two parts: a **processor** (`init` / `process` / `dispose`), which runs in the worker and has no access to the DOM, and a **renderer** (`draw`), which runs on the main thread. The result returned by `process` is sent from one to the other, so it must be [structured-cloneable](https://developer.mozilla.org/docs/Web/API/Web_Workers_API/Structured_clone_algorithm) (plain objects, arrays, typed arrays, `ImageData`, `ImageBitmap`…: no class instances with methods, no functions).

1. Create the processor, `src/algorithms/myAlgo.processor.ts`:

```ts
import type { FrameInput, Processor } from './types';

export interface Result { x: number; y: number }

export class MyAlgoProcessor implements Processor<Result | null> {
  async init(): Promise<void> {}

  process(frame: FrameInput, t: number): Result | null {
    // Sync or async. Only one run at a time: frames arriving during computation are skipped.
    return null;
  }

  // Optional: objects of the result to transfer instead of copying (e.g. a large typed array's buffer).
  // They become unusable in the worker: allocate new ones on each frame.
  // transferables(result: Result | null): Transferable[] { return []; }

  dispose(): void {}
}
```

2. Create the entry and the renderer, `src/algorithms/myAlgo.ts`:

```ts
import type { Result } from './myAlgo.processor';
import type { AlgorithmEntry, CoordMapper, Renderer } from './types';

class MyAlgoRenderer implements Renderer<Result | null> {
  draw(result: Result | null, ctx: CanvasRenderingContext2D, map: CoordMapper): void {
    // The canvas is cleared before each draw. Coordinates are those of `frame`.
    if (!result) return;
    const p = map.toScreen(result.x, result.y);  // → canvas pixels
    ctx.fillRect(p.x - 4, p.y - 4, 8, 8);
    // Alternative: map.applyTransform(ctx), then draw directly in source coordinates.
  }
}

export const myAlgo: AlgorithmEntry<Result | null> = {
  id: 'my-algo',
  label: 'My algo',
  input: 'imageData',  // or 'videoFrame' (WebCodecs), 'none' (no frame)
  maxInputWidth: 320,  // ImageData downscaled by the core, aspect ratio preserved
  backend: 'js-cpu',   // shown in the perf overlay
  // Called in the worker only. The dynamic import keeps the computation code out of the page.
  createProcessor: async () => new (await import('./myAlgo.processor')).MyAlgoProcessor(),
  createRenderer: () => new MyAlgoRenderer(),
};
```

3. Add it to the array in [src/algorithms/registry.ts](src/algorithms/registry.ts). That's it.

The registry is imported by both the page and the worker: entry modules must not touch the DOM at import time (only inside `createRenderer`).

**Heavy assets (models, WASM…).** The processor's `init` receives `{ signal, onProgress }` (in the worker). `onProgress(p, message)` feeds the loading indicator (`p` in [0, 1], or `null` if indeterminate). `signal` is aborted if the user switches algorithm in the meantime. Loading starts as soon as the app opens, while the user is granting camera permission.

```ts
async init({ signal, onProgress }: InitContext) {
  const res = await fetch(new URL('models/model.onnx', `${location.origin}${import.meta.env.BASE_URL}`), { signal });
  const total = Number(res.headers.get('content-length')) || 0;
  const reader = res.body!.getReader();
  const chunks: Uint8Array[] = [];
  let loaded = 0;
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    chunks.push(value);
    loaded += value.length;
    onProgress(total ? loaded / total : null, 'Downloading model');
  }
  // … initialize the runtime
}
```
